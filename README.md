# BiliMusic

把 B 站收藏夹 / 合集当歌单听的原生 Android 音频播放器。

**148 KB 的 APK，零第三方依赖，不用 Gradle，不用 Android Studio。**

## 这是什么

一个把 B 站收藏夹里的视频当音频听的小工具。登录自己的账号后，可以把收藏夹、追更的合集当播放列表来听歌。

**它不做的事**：不能看视频、不能发弹幕、不能评论、不能下载——只是一个播放器。

## 功能

### 登录
- 扫码登录（走 `passport.bilibili.com` 官方流程）
- 也支持手动粘贴 Cookie
- Cookie 只存在本机，不上传任何服务器

### 四类列表

| 类型 | 来源 | 能否编辑 |
|---|---|---|
| **收藏夹** | B 站服务端 | 只读 |
| **合集** | B 站「追更」的合集/系列 | 只读 |
| **BV 导入** | 粘贴 BV 号或视频链接导入 | 可删单曲、批量删 |
| **临时歌单** | 搜索结果一键保存 | 可删单曲、批量删、去重 |

- 收藏夹 / 合集支持长按多选隐藏，隐藏时自动清空对应缓存
- 支持按 id 选择性恢复隐藏项
- 从服务端同步时自动清理已失效的缓存（在 B 站取消订阅后不留垃圾）

### 跨歌单搜索
- 在全部本地缓存里模糊搜索，不限单个歌单
- 支持逻辑运算符，必须带方括号：
  - `陈奕迅` —— 包含该关键词
  - `陈奕迅[and]十年` —— 同时包含（顺序不限）
  - `陈奕迅[or]周杰伦` —— 包含任一
- 结果显示歌曲来自哪个 Tab 的哪个歌单
- 搜索结果不能直接播放，需先「生成临时歌单」——保证播放链路只有一条

### 临时歌单去重
- 归一化算法：全角转半角、去括号内容、去开头编号、去噪声词、去公共词
- 支持手动添加「自定义无效子串」，处理自动算法识别不到的冗长前缀
- 实时显示每个关键词命中了多少首
- 分组后默认每组保留第一首，可手动多选
- **宁可漏合并，不误合并**——漏了手动删，误了会丢歌

### 播放
- 点击即播，后台常驻前台服务
- 通知栏控制 / 锁屏控制 / 蓝牙耳机按键
- 三种播放模式：列表循环、单曲循环、随机
- 拖动进度条、断点续播、倍速播放（0.5x ~ 2.0x）
- 定时暂停（睡前听）
- 音质可选（64K / 132K / 192K）
- 自动跳过失效视频

### 其他
- 缓存管理（查看各类缓存占用）
- 退出登录一键清除所有本地数据

## 为什么值得看

如果你想了解「不借助 Gradle 和 Android Studio，怎么在命令行里直接产出一个 APK」，这个项目是一个完整可复现的例子：

| 特点 | 说明 |
|---|---|
| **不用 Gradle** | 纯 `aapt2 → javac → R8 → zipalign → apksigner` 脚本流水线 |
| **零第三方依赖** | 只用 Android Framework，没有 OkHttp / Retrofit / Glide / Room |
| **148 KB** | 对比同类项目小一个数量级 |
| **手写 JSON 持久化** | 没有任何 ORM，缓存与索引都是自己写的读写逻辑 |
| **完整的中文注释** | 关键决策点都写了「为什么这么做」 |

源码规模：**33 个 Java 文件，约 12600 行**。

## 安装

去 [Releases](../../releases) 页面下载最新的 `BiliMusic-x.y.z.apk`，直接安装。

**系统要求**：Android 7.0（API 24）及以上。

> **关于安装时的「开发者身份未验证」提示**
>
> 这是 Android 14+ 对「非 Google Play 渠道安装」应用的系统级提示，
> 与本项目无关。所有自签名 / 侧载应用都会遇到，不影响使用。
> 如果觉得每次安装都要多确认几步，可以用 `adb install` 安装。

- Windows：[BUILD-WINDOWS.md](BUILD-WINDOWS.md)

## 项目结构

```
BiliMusic/
├── src/com/star/bilimusic/
│   ├── api/        B 站接口封装、Wbi 签名、数据模型
│   ├── media/      封面加载（内存 LruCache + 磁盘缓存）
│   ├── net/        极简 HTTP 客户端
│   ├── player/     前台播放服务、MediaSession、通知栏、定时器
│   ├── ui/         Activity、各页面视图、配色
│   └── util/       Preferences、列表缓存、搜索、去重、任务调度
├── res/            资源文件
├── AndroidManifest.xml
├── build.ps1       Windows 构建脚本
├── build.sh        Linux / macOS 构建脚本
└── version.properties
```

### 几个设计要点

- **流式取流三级策略**：直链复用（20 分钟内）→ CDN 族记忆（约 90% 命中）→ 逐线路探测。把每首歌的取流开销从数百毫秒压到接近 `playurl` 接口本身的延迟。
- **`Track.key() = bvid + "_p" + page`**：B 站的多分 P 视频共用一个 BV 号，靠 `page` 区分，`cid` 才是播放时真正必需的参数。
- **搜索只匹配标题，不匹配作者**：这些标题实际是视频标题，通常已含歌手名；作者是 UP 主名字，匹配它反而引入噪声。
- **临时歌单存完整副本而非引用**：这样可以在临时歌单里单独删歌而不影响原歌单，也不会因原歌单刷新而失效。
